# SRT 视频重排剪辑器 · 设计文档

- 版本：v1.0
- 日期：2026-10-27
- 状态：方案已验证，待开工
- 适用场景：抖音直播切片；原视频 + 乱序 SRT → 成片 + 全部片段

## 1. 背景与目标

用户提供两样东西：

1. 一份原始完整视频
2. 一份从原始视频导出的 SRT，但条目顺序已被重新编排

系统只依据 **SRT 的时间戳** 到原视频中截取对应片段，并按照 **SRT 的条目顺序** 拼接，产出：

- `merged.mp4`：按 SRT 顺序拼接的完整成片
- `clips/`：与 SRT 条目一一对应的全部视频片段

SRT 文案只用于界面展示和人工核对，不参与定位，也不烧录进画面。

## 2. 真实样例实测结论

样例：

- 视频：`tests/完整的粗剪视频.mov`
- 字幕：`tests/剪辑后的文案.srt`

| 项目 | 实测值 |
|---|---|
| 分辨率 | 1080 × 1920（竖屏） |
| 帧率 | 30 fps（恒定帧率） |
| 视频时长 | 178.966667 s |
| 编码 | H.264 High + AAC LC 44.1kHz 双声道 |
| SRT 编码 | UTF-8 |
| SRT 条数 | 11 |
| SRT 原始总时长 | 56.166 s |
| 原片时间轴重叠 | 无 |
| 最小相邻间隔 | 0.067 s（第 5、6 条） |
| 切点位置 | 多数落在说话中间，非静音处 |

切片规划结果（默认无余量）：

- 严格按 SRT 时间戳，只做整帧对齐
- 总时长 `56.467s`，`1694` 帧
- 第 5、6 条间隔 `0.067s`，各自保留原边界（`88.567s` / `88.600s`）

可选余量模式（前 `0.10s`、后 `0.15s`）：

- 总时长 `59.167s`，`1775` 帧
- 第 5、6 条按间隔中点共享切点 `88.600s`，避免重复

实际生成验证：

- 11 个片段全部生成成功
- 成片：`56.467s`、`1694` 帧，与规划零误差
- 抽帧比对首尾画面，PSNR `40–44dB`，内容位置正确

## 3. 输入与输出

### 输入

- 视频：`.mp4 / .mov / .mkv` 等 ffmpeg 可解码格式
- SRT：UTF-8（兼容 BOM）、GBK/GB18030
- 可调参数：
  - 前余量，默认 `0.00s`
  - 后余量，默认 `0.00s`
  - 音频淡入淡出，默认 `0ms`（可改为 15ms / 30ms）
  - 精度模式：精确（默认）/ 极速
  - 画质档位：高（默认）/ 标准

### 输出

```text
data/jobs/<job_id>/
├── input/
│   ├── source.mov
│   └── source.srt
├── clips/
│   ├── 001_00-01-57.333-00-02-03.867.mp4
│   ├── 002_...
│   └── ...
├── merged.mp4
├── plan.json
└── job.log
```

- 文件名只包含序号与时间范围，包含字幕文案会带来非法字符和长度问题
- `plan.json` 记录每条字幕的原始时间、实际切点、帧号、输出文件，便于追溯
- 支持打包下载全部片段 `clips.zip`

## 4. 切点算法

### 4.1 步骤

```text
1. 解析 SRT，得到 cues = [{index, start, end, text}]
2. 对每条 cue：
   rawStart = max(0, start - padIn)
   rawEnd   = min(videoDuration, end + padOut)
3. 按原片时间排序，检查时间相邻的两条：
   若 gap = next.start - prev.end 且 0 <= gap < padIn + padOut：
       中点 mid = prev.end + gap / 2
       prev.rawEnd   = min(prev.rawEnd, mid)
       next.rawStart = max(next.rawStart, mid)
4. 帧对齐（30fps 为例）：
   frameStart = floor(rawStart * fps)
   frameEnd   = ceil(rawEnd * fps)
5. 对第 3 步共享中点的相邻对：
   sharedFrame = round(mid * fps)
   prev.frameEnd = sharedFrame
   next.frameStart = sharedFrame
6. 输出窗口使用帧号换算回秒数，保证片段时长是整帧
```

### 4.2 规则解释

- 默认余量为 0，严格按 SRT 时间戳
- 设置余量后，间隔足够大时前后余量完整生效
- 间隔不足时，两条共享间隔中点，不重复、不丢内容
- 帧对齐采用「起点向下取整、终点向上取整」，宁可多一帧，不丢帧
- 共享中点采用同一条帧边界，避免相邻片段在拼接时重复一帧

### 4.3 异常规则

| 情况 | 处理 |
|---|---|
| SRT 编码不是 UTF-8 | 依次尝试 UTF-8-SIG → UTF-8 → GB18030 |
| 时间格式使用 `.` 分隔 | 兼容 `00:00:01.000` |
| 缺少序号 | 允许，按出现顺序编号 |
| 多行字幕 | 合并为一行展示，不影响切点 |
| end <= start | 整单失败，列出错误条目 |
| start >= 视频时长 | 整单失败，列出错误条目 |
| end 超出视频时长 ≤ 0.25s | 截断到视频末尾并警告 |
| end 超出视频时长 > 0.25s | 整单失败 |
| 原片时间轴重叠 | 允许，按 SRT 各自切；成片会出现重复内容，界面明确警告 |
| 同一时间段重复出现 | 允许，按 SRT 重复输出，文件名序号不同 |
| 视频无音轨 | 允许，只处理视频，界面提示 |
| 可变帧率 VFR | 以 ffprobe 平均帧率做帧对齐，切点按时间裁剪；界面标记「VFR，时间精度可能受 1 帧影响」 |

## 5. 生成策略（已验证）

### 5.1 片段生成

每个片段单独执行一次 ffmpeg：

```text
ffmpeg -ss <start> -i source -t <duration>
  -map 0:v:0 -map 0:a:0?
  -c:v libx264 -preset medium -crf 18 -pix_fmt yuv420p
  -c:a aac -b:a 192k -ar 44100 -ac 2
  -af "afade=in...,afade=out..."
  -movflags +faststart
  clip.mp4
```

- `-ss` 放在输入前，快速定位且重编码后仍保持帧级准确
- 音频淡入淡出默认关闭（`0ms`），可开启 15ms / 30ms 用于消除乱序硬切产生的「咔哒」声
- 片段单独播放时完整、可直接用于发布

### 5.2 成片生成

**不能**把片段文件直接 `-c copy` 拼接。原因（实测）：

- 每个 AAC 片段带约 `23ms` 编码器填充
- 11 段直接拼接会累计约 `0.23s` 的音频/视频空隙，且时长与规划不一致

正确做法：成片用 **单次 ffmpeg 滤镜合成**：

```text
[0:v]trim=start=...:end=...,setpts=PTS-STARTPTS[v0];
[0:a]atrim=start=...:end=...,asetpts=PTS-STARTPTS,afade...[a0];
... 重复 11 次 ...
[v0][a0][v1][a1]...concat=n=11:v=1:a=1[outv][outa]
```

一次编码输出 `merged.mp4`：

- 成片时长、帧数与规划完全一致
- 音频只产生一次编码填充，无累计漂移
- 片段与成片使用同一套切点，内容一致

### 5.3 编码参数

| 档位 | 视频 | 音频 | 说明 |
|---|---|---|---|
| 高（默认） | libx264 / CRF 18 / preset medium | AAC 192k | 画质优先 |
| 标准 | libx264 / CRF 20 / preset veryfast | AAC 192k | 速度优先 |
| 极速 | `-c copy` | 直接复制 | 切点对齐关键帧，可能偏移 1–2s，必须明确警告 |

- 保持原分辨率、原帧率、原画面比例
- 输出统一为 MP4、`yuv420p`、`+faststart`
- 不烧字幕、不加转场、不做响度统一

### 5.4 极速模式说明

`-c copy` 只能从关键帧开始切，切点会漂移，且片段时长不精确。界面默认不选，选择时弹出提示：

> 极速模式按关键帧切，切点最多可能偏移 1–2 秒，仅用于快速预览。

## 6. 系统架构

### 6.1 技术栈

- 后端：Python 3.10 + FastAPI + ffmpeg / ffprobe
- 前端：React 18 + Vite + TypeScript + Tailwind CSS
- 运行方式：本机启动，浏览器访问 `http://127.0.0.1:8000`
- 不依赖数据库；任务状态存内存 + 文件系统
- 同一时间只处理一个任务，避免 ffmpeg 抢占 CPU

### 6.2 目录结构

```text
srt-video-cutter/
├── backend/
│   ├── app/
│   │   ├── main.py            # FastAPI 入口、静态文件托管
│   │   ├── api.py             # 路由
│   │   ├── models.py          # 数据模型
│   │   ├── srt_parser.py      # SRT 解析与编码识别
│   │   ├── planner.py         # 切点规划、帧对齐、异常校验
│   │   ├── ffmpeg_runner.py   # 片段与成片生成、进度解析
│   │   ├── jobs.py            # 任务状态机、单任务队列
│   │   └── storage.py         # 目录与文件管理
│   └── tests/
├── frontend/
│   ├── src/
│   │   ├── App.tsx
│   │   ├── components/
│   │   └── api.ts
│   └── ...
├── docs/DESIGN.md
└── tests/                     # 用户样例，不提交产物
```

### 6.3 任务状态机

```text
created → uploaded → planned → processing → completed
                                      ↘ failed
                                      ↘ cancelled
```

### 6.4 API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/jobs` | 上传视频 + SRT，返回 job_id |
| POST | `/api/jobs/{id}/plan` | 传入余量参数，生成切点预览 |
| POST | `/api/jobs/{id}/start` | 开始生成 |
| GET | `/api/jobs/{id}` | 查询状态、进度、日志、规划 |
| GET | `/api/jobs/{id}/preview/{file}` | 视频流预览，支持 Range |
| GET | `/api/jobs/{id}/download/{file}` | 下载单个文件 |
| GET | `/api/jobs/{id}/clips.zip` | 打包下载全部片段 |
| POST | `/api/jobs/{id}/cancel` | 取消任务 |
| DELETE | `/api/jobs/{id}` | 删除任务及产物 |
| GET | `/api/health` | 检查 ffmpeg / ffprobe |

### 6.5 进度

- 每个片段一条 ffmpeg 进程，解析 `-progress pipe:1` 的 `out_time_ms`
- 总进度 = 已完成片段数与当前片段百分比的加权
- 前端每 1 秒轮询一次；任务完成后停止轮询

## 7. 界面流程

1. 拖入视频和 SRT，显示文件名、大小、时长、分辨率、SRT 条数
2. 点击「解析并预览」
3. 展示切点表格：
   - 序号、原始起止、实际切起止、帧号、片段时长、字幕文案
   - 总时长、片段数
   - 原片重叠/越界/异常警告
4. 调整前余量、后余量、音频淡化开关、画质档位
5. 点击「开始剪辑」
6. 进度条 + 实时日志
7. 完成后：
   - 成片预览、下载
   - 片段列表预览、单独下载、打包下载
   - 显示输出目录路径
8. 出错时显示具体原因与错误条目，不静默失败

## 11. 风险与对策

| 风险 | 对策 |
|---|---|
| SRT 时间戳与画面不同步 | 界面提供片段预览，人工抽查 |
| SRT 条目重叠导致成片重复 | 解析阶段明确警告，按用户要求保留 |
| 极速模式切点漂移 | 默认关闭，选择时强提示 |
| 长视频大量片段导致滤镜图过大 | 每 20 段分组合成后无损拼接，进度分段显示 |
| 磁盘占用 | 任务列表显示占用，支持一键删除任务目录 |
| ffmpeg 版本差异 | 启动时检查 ffmpeg/ffprobe 并显示版本，低于 6.0 提示升级 |

## 12. v1.1 新增：提示词切片（AI 生成切片 SRT）

在原有「SRT 驱动剪辑」之前加了一层「完整 SRT → 切片 SRT」：

```text
完整视频 + 完整 SRT
  → 生成候选开头钩子（hooks.md）
  → 用户选一个钩子
  → 生成切片 SRT（clip.md）
  → 复用原有 plan / start 流程剪出成片
```

### 12.1 模块划分

| 模块 | 职责 |
|---|---|
| `backend/app/llm.py` | 读取 `.env`/环境变量，调用 OpenAI 兼容接口或本地 Ollama |
| `backend/app/clip_writer.py` | 构建提示词、解析 JSON、校验区间、输出 SRT |
| `backend/app/prompts/*.md` | 钩子提示词与切片提示词，可直接改文案调效果 |
| `backend/app/jobs.py` | 任务级状态：hooks、selected_hook_id、clip_srt、generation |
| `frontend/src/components/HookSelector.tsx` | 钩子单选、生成切片、下载/重置 |

### 12.2 数据流约束

- 模型只输出条目编号 `[a, b]`，文案和时间戳一律由后端从原 SRT 取；
- 单条成片字幕必须是连续相邻块，重叠区间直接判失败并重试；
- 钩子必须出现在成片中，并强制排在第一条；
- 切片 SRT 的时间戳沿用原片，因此成片 SRT 的时间戳不递增是正常的；
- 生成切片后会自动执行一次 `plan`，前端拿到的是可直接开剪的状态。

### 12.3 状态

`Job.generation_status`：`idle → generating_hooks → hooks_ready → generating_clip → clip_ready`，
失败为 `failed`（错误信息放 `generation_error`）。

### 12.4 与旧流程的兼容

- 上传接口不变；旧版「直接上传重排 SRT」仍可用；
- 前端上传区提供两种模式卡片：
  - **AI 智能切片**：上传后自动生成开头钩子（原有流程）；
  - **手动重排剪辑**：上传后直接按 SRT 时间戳 `plan`（旧版流程，不调用 AI）；
- AI 流程中仍保留「跳过 AI，直接用原 SRT」，走原有 `plan` 流程；
- 手动模式生成切点后，仍可点「改用 AI 生成开头钩子」切回 AI 流程；
- `POST /api/jobs/{id}/reset-clip` 可随时回到完整字幕。
